## 2. Структурированное техническое задание

### 2.1. Смысл и пользователь

**Рабочее название истории:** Git за неделю

**Основной посетитель:** начинающий разработчик

**Главная мысль:** после просмотра посетитель должен понять, что базовый Git можно освоить за короткий срок и увидеть его практическую ценность в разработке.

**Желаемое впечатление:** история должна восприниматься как спокойная, понятная и личная.

**Главное действие посетителя:** прочитать историю и при желании перейти к дополнительному материалу по Git.

### 2.2. Содержание истории

**Контекст:** Git всё чаще встречался в учебе, на стажировках и хакатонах, но оставался заметным пробелом в навыках.

**Центральное действие, выбор или идея:** герой записался на недельный летний мини-курс по Git в вузе, чтобы системно разобраться с основами.

**Результат или предполагаемый эффект:** герой освоил базовый Git и понял, почему этот инструмент широко используется в разработке.

**Почему это раскрывает человека:** история показывает стремление закрывать пробелы в знаниях и разбираться в важных для профессии инструментах.

#### Три обязательных факта

| № | Структурированный факт | Зачем он нужен посетителю |
| --- | --- | --- |
| 1 | Git позволяет отменять изменения и возвращаться к рабочему состоянию проекта. | Показывает пользу контроля версий при ошибках. |
| 2 | Git помогает нескольким разработчикам работать над одним проектом. | Показывает пользу инструмента для совместной работы. |
| 3 | Git позволяет работать с удалёнными репозиториями и публиковать код. | Показывает, как изменения передаются и хранятся вне локального компьютера. |

| 3. Завершение | Итог истории и рекомендацию для дальнейшего изучения. | Итоговый блок и ссылка | В конце страницы есть вывод и ссылка на Pro Git. |

**Обязательные части страницы:**

- первый экран с героем и главной мыслью;

**Что сознательно не добавляем:** подробное описание команд Git и внутренних механизмов его работы.

### 2.4. Визуальное направление

**Тон оформления:** спокойный, простой, тёплый

**Главный визуальный акцент:** история героя и три практических вывода.

**Пожелание заказчика:** не перегружать страницу большим количеством блоков и декоративных элементов.

**Что заказчику точно не подходит:** сложная структура и оформление, которое мешает читать историю.

### 2.5. Технические требования

- Страница реализуется без JavaScript.
- Используется семантическая HTML-структура.
- На странице присутствует только один `h1` и сохраняется последовательная иерархия заголовков.
- Минимум одна линейная группа элементов собрана через Flexbox.
- Минимум один набор элементов собран через Grid.
- Повторяющийся компонент использует согласованные БЭМ-имена классов.
- На ширине около 360 px нет горизонтального скролла и перекрытия элементов.
- На ширине около 1200 px контент не растягивается до нечитаемой длины.
- Интерактивные элементы доступны с клавиатуры и имеют видимый focus.
- Ссылки имеют понятный текст и ведут по корректному адресу.
- Используются только разрешённые заказчиком сведения.
